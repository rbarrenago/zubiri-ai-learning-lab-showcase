Primero ordenamos las piezas.
Después construiremos un castillo.

El futuro robot dispone de 21 piezas diferentes. Antes de colocarlas, debe agruparlas a partir de medidas geométricas. Para ello usamos K-means, sin decirle de antemano a qué grupo pertenece cada pieza.

La misión: preparar los materiales para un castillo

Imagina una mesa con 21 bloques de distintas anchuras y alturas. Queremos organizarlos en tres bandejas antes de construir un castillo con tres torres. El algoritmo no conoce las palabras «base», «muro» o «torre»: solamente recibe las medidas de ancho y alto de las piezas. Nosotros decidiremos después cómo utilizar los grupos.

¿Qué está haciendo el algoritmo?

Empezamos con centroides iniciales. El siguiente paso asigna cada pieza al centro más cercano.

Las dos operaciones

  1. Asignar: cada pieza va al centroide más próximo.
  2. Actualizar: cada centroide se mueve a la media de sus piezas.
Los colores son resultados del agrupamiento, no etiquetas proporcionadas al algoritmo. El plan para construir un castillo es una decisión externa, posterior a K-means.

¿Qué haría el UR3e?

  1. Una cámara observaría las piezas; el sistema mediría o estimaría sus características.
  2. K-means propondría grupos sin etiquetas conocidas.
  3. El robot depositaría las piezas en zonas predefinidas según el grupo.
  4. Una receta de construcción externa escogería piezas y movimientos seguros para el castillo.

Aquí la geometría, las piezas y el castillo son ilustrativos. Una manipulación física real requeriría visión, agarres, límites y evaluación de riesgos.

La idea que queremos comprender

Datos sin etiquetas → similitudes entre piezas → agrupamientos → organización física posible. K-means no sabe qué es un castillo; descubre estructuras matemáticas que después podemos aprovechar para una tarea.
